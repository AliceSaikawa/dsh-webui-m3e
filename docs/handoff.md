## 部品集の比較の要点（サブエージェントの調査、2026-09-25）

- **@m3e/web 2.8.2 + @m3e/react**
  - MIT ライセンスで、週のダウンロード数は約 1,300 です。
  - 必要な 15 種類の部品がすべて揃っています。ボトムシートは、途中で止まる位置の指定、払って隠す操作、つまみに対応しています。
  - 公式の React ラッパーがあります。
  - Material Symbols のフォントは別に読み込む必要があります。スナックバーは命令的な API で呼び出します。
  - JSX で使うときの注意：`for` 属性は `htmlFor` と書きます。`hideSubscript` は文字列で指定します。
- **@language-lit/material3-expressive 1.2.2**
  - React 用に作られた部品集で、Tailwind は不要です。BottomSheet、SegmentedListItem、NavigationBar があります。
  - 利用者が少なく（週のダウンロード数 50）、CSS は 52KB を一括で読み込みます。シード色からの配色生成はありません。
- 除外したもの：banegasn（ボトムシートがない）、react-material-expressive（保守が止まっている）、juicer-m3、m3x、bug-on（Tailwind が必須）。

## 部品集の実機比較（Simulator、2026-09-25）

iPhone 17 Pro Max（iOS 26.2）で、Safari とホーム画面に追加した Web アプリの両方で確かめました。テスト用のページは `tmp/libtest`（git 管理外）にあり、`pnpm dev` で 127.0.0.1:5190 に開きます。URL に `?chat` を付けると会話画面から始まり、`?fill` を付けると入力欄に 8 行を入れます。画面左上の HUD に、画面の高さ、`visualViewport`、safe-area の値が出ます。

| 確認したこと | @m3e/web + @m3e/react | @language-lit |
|---|---|---|
| シートを指で払って閉じる | 1 回の引き下げで閉じます | 1 回目は半分開いた状態で止まり、2 回目で閉じます。つまみからしか引けません |
| シートを開いたときの背景 | 動きません | 動きません |
| バッジ | React の `htmlFor` では `for` 属性が付かず、枠の外に出ます。ref で `setAttribute('for', アイコンの id)` とすると、アイコンの右上に正しく付きます | 「3」が赤い丸なしでアイコンに重なります（原因は調べていません） |
| safe-area | どの部品も扱いません。自分で余白を付けます | シートの下だけ余白を付けます。ナビゲーションバーには付けません |
| 入力欄の自動伸長 | `M3eTextareaAutosize` で 6 行まで伸び、その先はスクロールします | 機能がありません |
| シートの見た目 | 余白が付いています | 本文に余白がなく、開いたときに青いフォーカス枠が出ます |

- **キーボード**：どちらの部品集でも、何もしないと Safari がページ全体を上にずらし、上のバーが画面の外に出ました。画面の枠を `position: fixed` にして、`top` と `height` を `visualViewport` の `offsetTop` と `height` に合わせると、上のバーを残したまま入力欄がキーボードのすぐ上に来ました。閉じると元に戻ります。部品集の差ではないので、本実装でもこの組み方を使います（`tmp/libtest/src/hud.tsx` と `shared.css`）。
- **safe-area**：Safari の中では上下とも 0 です。ホーム画面から開くと、下が 34、上が 0 でした（ステータスバーの設定が既定のため、ページはステータスバーの下から始まります）。下のナビゲーションバーとシートには、`env(safe-area-inset-bottom)` の余白を自分で付け、その部分にもバーと同じ背景色を塗る必要があります。
- Simulator のホーム画面に、テスト用の「m3e」アイコンを追加しました。不要なら長押しで削除してください。
- シミュレーターの文字入力は日本語入力を通るため、改行が確定として扱われます。入力欄の伸び方は `?fill` で確かめてください。

## 環境のメモ

- **Mac の本物の DSH**：launchd の `com.user.deepseek-harness-web` から起動され、`127.0.0.1:3081` で動いています。ログイン URL は `~/AI/tmp/deepseek-harness-web/stdout.log` に出ます。トークンの扱いは自動モードで止められるので、開くのはユーザーに頼んでください。
- **検証用の DSH**：本番から切り離した空の `DSH_HOME` を使い、`dsh --profile web --no-open --port 3199` で起動します。前のセッションのものは、作業用フォルダと一緒に使えなくなります。作り直す手順は次のとおりです。
  1. `pnpm build && pnpm pack` を実行します。
  2. `DSH_HOME=tmp/dsh-home dsh plugin --profile web add file:<tgz>` でプラグインを入れます（`tmp/` は git 管理外です）。入れ直すときは version を上げてください。
  3. 最初に出る「Internal Testing Notice」は、情報を知らせるだけの画面です。API キーの画面は「Configure later」で飛ばせます。
- AI のコミットに付けるトレーラ（`AI-Harness` など）は、このセッションでは付けていません。システムの指示で、帰属表示を付けないよう求められたためです。
