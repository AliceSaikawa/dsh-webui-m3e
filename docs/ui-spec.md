# 画面の仕様

2026-09-25 に、この仕様と Canvas の最新版（41 画面）を現段階の決定としました。機能ごとの設計書は `docs/design/` にあります。細かい見た目と文言は、実装したものを見てフィードバックで詰めます。

M3E Canvas のモックと、会話で決めたことをまとめたものです。データの出どころは `~/AI/inbox/2026-09-17-dsh-webui-m3e-api-surface.md`（DSH 0.1.5-rc.1 の API 調査）を正とします。

## セッション一覧（ホーム）

- **上のバー**：左に ≡、中央にタイトル、右に ⋮ を置きます。
  - ≡ はワークスペースを切り替えるドロワーを開きます（下の「ワークスペースの切り替え」）。
  - タイトルは、今いるワークスペースの名前です。
  - ⋮ の中身は下の「一覧の ⋮ メニュー」のとおりです。
- **一覧の行**
  - 左のアイコンは、そのセッションのモデルのアイコンです。`projectionValues.modelSelection.lastUsed` の提供元とモデル名から選びます。アイコンは SVG で同梱し、該当がなければモデル名の頭文字を出します。値のない行もありえます。
  - アイコンの右下に状態の印を重ねます。対象は、実行中、完了して未読、承認待ち・質問待ちです。
  - 1 行目はタイトル（`displayTitle`）、2 行目は「作業フォルダ名 ・ 最終更新日時」です。最後のメッセージは一覧のデータにないので出しません。
  - 横スワイプでアーカイブします（任意）。
- **右下の FAB**：＋ で「新しいセッション」の画面を開きます。今のワークスペースに作ります。
- **ナビゲーションバー**：一覧、検索、対応待ち、設定の 4 つで、この順に並べます。
  - ラベルは「一覧」「検索」「対応待ち」「設定」です。
  - 対応待ちのアイコンは手のひら（`front_hand` 系）で、件数のバッジを付けます。
- **余白**：一覧の最後の行が、FAB、ナビゲーションバー、iPhone のホームバーに隠れないようにします。

## ワークスペースの切り替え

- 一覧の ≡ で、左から出るナビゲーションドロワーです。右側は暗くし、タップすると閉じます。
- ワークスペースを並べ、今のものを選択中の見た目にします。1 行は名前とフォルダの場所です。選ぶと一覧がそのワークスペースに切り替わります。
- 長押しで、名前の変更（`workspace.rename`）、並べ替え（`insertBefore`）、登録の解除（`workspace.delete`）を選べます。登録を解除しても、フォルダの中身は消えません。
- 最後の行は「ワークスペースを追加」で、「フォルダの選択」を開きます。

## フォルダの選択

- DSH が動いている機械のフォルダを、1 階層ずつたどって選びます（`directoryPicker` の `browse`）。iPhone からは OS のフォルダ選択（`native`）が使えないためです。`directoryPicker` が使えないときは、「ワークスペースを追加」自体を出しません。
- 上に閉じるボタン、その下にパンくず（今いる階層までの道のり。タップでその階層に戻る）を置きます。
- フォルダの行をタップすると 1 階層下に入ります。隠しフォルダは出しません。1,000 件を超えると一部だけになる（`truncated`）ことを小さく知らせます。
- 下に「新しいフォルダ」（`createDirectory`）と「ここを追加」（`workspace.create`。登録済みなら既存のものを返す）の 2 つのボタンを並べます。

## 新しいセッション

- 一覧の ＋ で開く、まだ何も話していない会話です。中央に「何をしますか」と、どのワークスペースで始めるかを出します。入力欄は会話画面と同じです。
- **セッションは、最初のメッセージを送った時点で作ります**（`sessions.create`。2026-09-25 決定）。何も送らずに戻ったら作りません。空のセッションを一覧に残さないためです。

## 一覧の ⋮ メニュー

中身は下の「有力な候補」の 4 つです（2026-09-25 決定）。項目を選ぶか、外側をタップすると閉じます。検討した候補と、それぞれの根拠は次のとおりです。

- 有力な候補
  - **並べ替え**：一覧の手動の並び順を変えるモードに入ります。ワークスペースが手動順（`sessionIds`、`insertSessionBefore`）を持っているので作れます。
  - **選んでアーカイブ**：複数の行を選んで、まとめてアーカイブします（`archiveSession` を 1 件ずつ呼ぶ）。
  - **ワークスペースの名前を変える**：今のワークスペースに対する操作です。ドロワーの長押しと同じ操作を、見つけやすい場所にも置きます。
  - **サブエージェントのセッションを表示**：切り替えスイッチです。一覧の 1 件は `origin: 'subagent'` と `parentId` を持てるので、隠すか出すかを選べます。一覧に実際にサブエージェントの行が来るかは未確認です。
- 保留する候補
  - **アーカイブ済みを表示**：アーカイブ済みの一覧（`archivedSessionIds`）は取れます。ただし、アーカイブを戻す専用の API は、Mac の DSH 0.1.5-rc.1 の型定義にありません。`insertSessionBefore` で戻せるかは未確認です。見られても戻せないなら、価値が下がります。
- 外す候補
  - **読み直す**（`sessions.refresh`）：一覧を下に引っぱって読み直す操作で足ります。
  - **再接続**：接続が切れたときのバナーにボタンがあります。
  - **使用量・クォータ**：第 1 弾ではクォータを出さない方針です（API 調査メモ §9.10）。トークン数もセッションごとの値で、一覧全体の値はありません。

## 接続が切れたとき

- 一覧の上のバーの下にバナーを出します。中身は「DSH との接続が切れました」、表示しているデータが何分前のものか、「再接続」ボタン（`connection.reconnect()`）です。
- 再接続の途中は、上のバーの下に細い進捗バーだけを出し、失敗したらバナーに切り替えます。PWA を裏に回して戻ると再接続が走るので、状態を出さないと固まったように見えるためです。
- 接続が切れている間は、＋ ボタンを押せなくします。

## 検索タブ

- セッションを全文検索します（`sessions.search`）。ファイルの中身は検索できません。
- 上に検索バーを置きます。入力を止めて少し待ってから検索し、前の検索は取り消します（`AbortSignal`）。
- 結果の行は、1 行目が題名、2 行目が一致した箇所の抜粋で、一致した語を強調します。結果の 1 件に抜粋が入っているか（`SessionSearchResultItem` の中身）は未確認です。
- `hasMore` が true のときだけ、最後に「さらに読み込む」を出します。

## 対応待ちタブ

- 自分の操作が必要なセッションだけを並べます。対象は、ツールの承認待ち、AI からの質問待ち、プランの承認待ち、完了して未読のものです。
- 2 つの区分に分けます。「返事が必要」（承認・質問・プランの確認）と「終わったもの」（完了して未読）です。
- 「返事が必要」の行をタップすると、会話を開かずに、承認や質問のシートを対応待ちの画面の上に直接出します。プランの確認は、質問の一種（`intent: plan-review`）として届きます。本文が長いので、全画面のシートにします。
- 「終わったもの」の行をタップすると会話を開きます。開くと既読になり、この画面から消えます。

## 設定タブ

- 上の区分は「この端末」で、この端末だけの設定です。
  - 「今の画面に戻す」：Cookie `dsh-webui` を `classic` にして `/` へ移ります。
  - 「外観」（明暗）：この端末だけで持ち、DSH の `ui-theme` とは共有しません（2026-09-25 決定）。
- 下の区分は「DSH の設定」で、DSH 全体の設定です。名前空間ごとのスキーマから、画面を自動で作ります。12 個の名前空間を次の 5 行に束ねます。
  - モデル：`agent-default-model` は「提供元 / モデル名」と推論の強さをドロップダウンで選び、`subagent-model-selection` は有効の切り替えと許可するモデルのチェックで選びます。推論の強さは対応モデルだけに表示し、一覧にない保存済みモデルも残します。
  - 権限：`permission`
  - エージェント：`agent-presets`、`agent-loop`
  - 提供元と API キー：`llm-*` と認証情報。キーは書き込むだけで、登録済みかどうかだけを出します。
  - Web 検索とシェル：`web-search-deepseek`、`shell`、`locale`
  - `ui-*` と `ui-onboarding` は今の画面向けなので出しません。
- 設定の詳細ページ
  - 各項目の補足に、反映のタイミングを出します（`applies` が `live` ならすぐ、`restart` なら再起動後）。
  - ユーザーが上書きした項目（`user` に値がある）には「既定値に戻す」を出します。
  - `writable` が false なら、全部の項目を無効にします。書き込みが競合（`settings/conflict`）したら、読み直しを促します。

### カスタムプロバイダーの追加・編集（Issue #16）

対象は DSH 0.2.0-rc.2 のカスタム提供元です。実装と追加の実測は [08 の実装メモ](design/08-settings.md#実装メモ) に記録します。偽データの「設定だけ成功」の接続差分 `tmp/handoff-issue16-01.md` は `ad192ba` で適用済みです。

#### 入口と画面の形

- `#/settings/providers` の「提供元と登録状況」の直下に「カスタムプロバイダーを追加」を置きます。提供元ごとのまとまりには名前・ID・キーの登録状況を表示し、カスタム提供元だけに「編集」を置きます。参照名が設定済みなら「API キー」も別のボタンとして置きます。キーを変更できないとき（キーの保存先だけが読み取り専用、など）は、ほかの行と同じく、登録状況のあとに「（変更できません）」を添えて、「API キー」を無効にします。キーを変更できなくても、設定が書き込み可能なら「編集」は使えます。ボタンの中に別のボタンを入れません。
- 編集対象は Host がカスタムとして宣言し、設定先が対応する提供元のものだけです。カタログ内の標準提供元を、名前や稼働状態からカスタムと推測しません。
- 追加と編集は同じ**全画面シート**を使います。見出しは「カスタムプロバイダーを追加」「カスタムプロバイダーを編集」。編集では提供元の名前と ID も示します。見出しの右に「閉じる」、本文の末尾に左「キャンセル」、右「保存」を置きます。URL は元のページのままです。
- 選択理由：一度の「保存」で完結する操作なので、既存の `openFullSheet` に合わせます。新しいルート案は履歴、直接アクセス時の復元、戻る制御が必要になるため今回は採用しません。単一の文字入力用ダイアログは、モデルの複数行やエラーを置くには狭いため使いません。

#### フォームとモデルの行

縦一列で次の順に並べます。文字は自動大文字化・スペルチェックを無効にします。ID は空白を含めてそのまま扱います。URL は前後の空白を除いた値を検査・保存します。入力やフォーカス移動では保存しません。

| 順 | 欄 | 操作と補足 |
|---|---|---|
| 1 | プロバイダー ID | 追加時は非空で、既存の ID と重ならない値。例は `my-provider`。大文字・下線・点・数字始まりなども許可します。既存 M3E の設定パスが扱わない `__proto__` / `constructor` / `prototype` は禁止。「英字で始まる ID を推奨します。数字で始まる ID は、キーを空欄にして作成できます。」と案内します。編集時は変更不可 |
| 2 | 表示名（任意） | 空欄では ID を表示名に使います。既存の上書きを消す場合は、継承する名前があればその名前へ戻ります |
| 3 | ベース URL | 必須。前後の空白を除いて `http://` または `https://` で始まり、URL として解析できる値だけを保存します。localhost、IPv4、IPv6、ポート指定は許可します。空白だけ・不正な URL・別スキームは欄エラーで保存を止めます。「前後の空白は保存時に除きます」と、URL にキーを書かない案内を添えます |
| 4 | API プロトコル | Host のスキーマが返す候補だけを表示します。表示は「OpenAI チャット補完」「OpenAI 応答」「Anthropic メッセージ」。初期値は Host の先頭候補。候補なしなら保存できません。編集時に候補外の値があれば「現在の値は選択肢にありません」と示し、勝手に選び直しません |
| 5 | モデル | 1 件以上。追加時は空の 1 行から始めます。各行はモデル ID と任意の「モデル表示名」、折りたたむ「詳細」、行末の「モデルを削除」。一覧の末尾に「モデルを追加」を置きます |
| 6 | API キー（任意） | 「保存すると、あとから表示できません」「空欄なら登録済みのキーを変更しません」。登録状態は「登録済み」「未登録」「確認できません」、参照先がない既存行は「未設定」。新規作成時も空欄で保存できますが、認証が不要とは断定しません |

ID とキーの参照名は別の制約です。参照名は `^[A-Za-z_][A-Za-z0-9_]*$` に合う必要があります。数字始まりの ID も、ほかの参照先なしカスタムと同じく一覧では「API キー：未設定」と表示し、照会もキー入口も設けません。編集フォームではキー欄の近くに、導出名では登録できない理由と「キーを空欄にすると、設定だけ保存できます。」を示します。入力欄は残し、キーを入力して保存した場合は欄エラーで止めます。既存の提供元に有効な参照名が明示されていれば、数字始まりの ID でもその参照名を使えます。

ID を標準画面と同じ小文字英字・ハイフンへ絞る案は採用しません。Host が扱えるキーなしの提供元を不必要に排除せず、キー付きの操作だけを参照名の形式と実際の保存先の重複で検査します。一方、URL は Issue の明示要件を優先し、Host の受理範囲より画面の条件を狭くします。

- モデルの編集はシート内のその行で行います。別の重なる入力シートは開きません。「詳細」は「コンテキスト長」「最大出力トークン数」「入力種別」の順です。数値は任意、指定するなら 1 以上の整数。空欄では提供元の既定値を使うと示します。入力種別は「提供元の既定値を使う」を初期状態とし、明示する場合は「テキスト」「画像」をチェックします。少なくとも 1 つ選びます。選択肢はスキーマにあるものだけです。
- モデル ID は空欄と同じ一覧内の重複を認めません。行は画面内の安定した識別子で管理し、入力で ID が変わってもフォーカスが移動しないようにします。削除は下書きにだけ反映し、即時保存も削除確認ダイアログも出しません。最後の行の削除も下書きでは許可し、「モデルを 1 件以上追加してください。」を一覧の下に表示して保存を止めます。
- 保存済みの詳細にこのフォームで扱わない値があれば保持します。伏せられた子の値を含むモデル一覧は、このフォームから置き換えず、編集できない理由をモデル欄に出します。表示名など安全に変更できる欄は使えます。
- API キーは伏せ字が初期状態です。「入力したキーを表示する／隠す」は今回入力した文字だけが対象です。送信開始時に入力欄と表示状態を消し、失敗しても戻しません。キャンセル・閉じる・戻る・画面破棄でも消します。キーの登録削除は既存の「API キー」の入口で行い、このフォームの空欄では削除しません。

#### 入力エラーと保存

一度触れた欄を離れたときと保存時に検査し、欄の直下に日本語のエラーを出します。保存時は最初のエラー欄へフォーカスし、スクロールして見える位置へ移します。モデルのエラーは該当する行・欄に結び付けます。入力前から全欄を赤くしません。

| 条件 | 文言 |
|---|---|
| ID が空 | プロバイダー ID を入力してください。 |
| ID が予約名 | この ID はこの画面では使えません。別の ID を入力してください。 |
| ID が既存の提供元・カタログ・設定と重複 | このプロバイダー ID は使われています。別の ID を入力してください。 |
| URL が空 | ベース URL を入力してください。 |
| URL が不正／HTTP・HTTPS 以外 | http:// または https:// で始まる URL を入力してください。 |
| プロトコルが未選択／候補外 | API プロトコルを選んでください。 |
| モデル ID が空／重複 | モデル ID を入力してください。／このモデル ID は同じ一覧にあります。 |
| 数値が不正 | 1 以上の整数を入力してください。 |
| 明示する入力種別が空 | 入力種別を 1 つ以上選んでください。 |
| キーの書式が不正 | API キーに改行や制御文字は使えません。 |
| キーの参照名が不正 | キーの参照名が DSH の形式に合わないため、この提供元には API キーを登録できません。 |
| 新しい参照名が他の提供元と重なる | 参照名「導出名」：別の提供元とキーの参照名が重なります。キーを空欄にするか、ほかと重ならない接頭辞を付けた ID（例：my-local-api）で追加してください。 |
| 新しい参照名が標準の予約名 | 導出名に続けて「標準の提供元が使う名前として予約されています。」。接頭辞の予約なら「AWS_ で始まる名前は標準の提供元の補助設定として予約されています。」など。別 ID の例も出します |
| 新しい保存先にキーが登録済み | 導出名に続けて「この名前のキーはすでに登録されています。」と別 ID の例 |
| 新しい保存先の状態が取れない／書込み不可 | 導出名に続けて「登録状況を確認できません。接続を確認して、もう一度お試しください。」／「この保存先は変更できません。」 |

参照名を持たないカスタム行は「API キー：未設定」と、`API キーは「編集」から登録できます。` を表示します。参照名を導出せず、登録状況の照会に含めません。「API キー」の入口は出さず、「編集」だけを出します。キーが不要とは判断しません。数字で始まる ID や、多数のキーなし提供元を追加しても、既存の照会先は増えません。設定トップの件数も「未設定」に分けます。

新しい参照を付ける場所は追加・編集のフォームだけです。キーを入力し、まだ参照先がない場合、フォームを開いた設定で他の提供元の明示名と照合します。照合するのは名前だけで、名前を明示している提供元がどれか（名前空間や ID）によって除外することはありません。ID に `/` を含むカスタムプロバイダーでも、別の名前空間の提供元が明示した名前と重なれば止めます。標準の既定名（`OPENAI_API_KEY`、`GEMINI_API_KEY` など）と `AWS_` / `GOOGLE_` / `GCLOUD_` / `CLOUDFLARE_` の接頭辞も予約します。別のキーなしカスタムの ID から想像した名前は予約しません。参照名は大文字・小文字を区別します。保存時に 1 件の登録状況を追加照会し、登録済み・確認不能・書込み不可ならキー欄のエラーで止めます。確認の待機中も保存中として操作を無効にします。

参照名を明示している行と、参照名のない標準の行は、Issue #16 前の main と同じ状態表示・登録・削除を保ちます。2 行が同じ参照名を明示している場合は、利用者が意図した共有として操作できます。共有先のキーを削除すると両方に影響するため、従来の削除確認の説明を維持します。前回入れた「既存の明示共有も変更不可にする」制限は外しました。

参照名は、フォームを開いた revision を付けた設定差分の中で保存します。同じ名前空間に別の変更があれば競合として停止します。設定成功後に別画面が同じ参照を明示した場合は意図した共有として扱い、後から衝突を検査し直しません。部分成功後は設定を再送しません。

ただし、別の名前空間の設定と、キーの保存先は、この revision では守られません。そこで、**フォームがこの保存で新しく付けた参照名にかぎり、キーを送る直前に登録状況を読み直し、その名前のキーが登録済みになっていたら、キーを送らずに止めます**（保存先を確かめたあとで、別の画面が同じ名前を明示してキーを登録した場合です）。フォームを開いている間は、同じシートでの再試行でも、シートの中で設定を読み直したあとでも、設定の保存の応答を失って「保存結果を確認」を押したあとでも、同じ確認を続けます。フォームを開き直したあとは、参照名を設定に明示されたものとして読み込むので、一覧からの登録と同じく、通常のキー保存を行います。

読み直しからキーの送信までの、ごく短い時間差は残ります。DSH のキーの保存先には「未登録のときだけ書く」操作が無いため、画面の側だけでは無くせません。Issue #16 の前からある、参照名のない標準の提供元に参照先を付けてからキーを書く流れにも、同じ時間差があります。これは既存の制限として扱います。

参照名が設定済みでキーが未登録なら、一覧と編集フォームに「キーの参照先だけが設定されています。キーを登録するまで、この提供元を使えない場合があります。」を表示します。参照先保存の応答を待って閉じた場合も同じです。次に開いたときは保存済みの明示参照を main と同じく扱い、空のキー欄から登録できます。設定の参照名は重ねて追加しません。自動追加と利用者による明示を保存データで区別する制限は設けません。

一覧の照会・登録・削除は main と同じ 1 回の照会を使います。拒否・不正応答なら不明状態と一部確認不能の案内、例外なら一覧の取得失敗の案内です。標準の未稼働提供元が参照先を付ける既存の流れも維持します。以前の分割処理と追加試験（04・05）は `c015aee` で適用されましたが、今回の設計では廃止しました。一括照会へ戻す差分（06）と、フォーム専用の 1 件の照会の接続（07）は `6652683` で適用済みで、分割処理のファイルは残っていません。

- 保存ボタンは、取得不能・読み取り専用・切断・保存中・再確認待ちでは無効です。通常の入力不足は押すと該当欄に案内します。変更のない編集では「保存」を無効にします。
- 保存中はフォームの編集と保存を無効にし、「保存しています…」を状態として通知します。Enter の連打、ボタンの連打でも一度だけ送信します。モデル欄での Enter でフォーム全体を誤送信しません。
- 設定とキーの両方が成功したらシートを閉じ、「提供元を保存しました」を表示して一覧を読み直します。キー空欄なら設定だけで正常完了です。モデル選択・会話・既定モデルは変更しません。開き直すと保存済みの値を取得します。

#### 保存できない場合

欄ごとの入力エラー以外は、見出しの下に消えない案内と必要な操作を置きます。下書きの通常項目は保持します。キーは送信開始後や切断時に保持しません。英語の Host エラーや入力したキーをそのまま画面・通知へ出しません。

| 状態 | 表示と操作 |
|---|---|
| 読み取り専用 | 「この DSH では設定を変更できません」。追加・保存を無効にし、保存済み内容は確認できます |
| 対象の設定がない | 「この DSH ではカスタムプロバイダーを設定できません」。追加を無効にします。編集中に消えた場合は保存を止めます |
| 設定・提供元・候補の取得失敗 | 「設定を読み込めませんでした。接続を確認して、もう一度お試しください。」と「再読み込み」。空の設定で既存値を代用しません |
| 切断・結果不明 | 「接続が切れました。保存できたか確認してから、もう一度お試しください。」。再接続後も勝手に送らず、「保存結果を確認」で読み直します |
| 競合・編集中の外部変更 | 「ほかの場所で設定が変わりました。再読み込みして、変更内容を確認してください。」と「再読み込み」。押す前に「入力中の変更は破棄されます」と示します。新しい値と revision を取り直してから再編集します |
| Host の拒否 | 「この変更は保存できませんでした。入力内容を確認してください。」。対応が確実な欄だけ欄エラーも出します。下書きを残し、自動再送しません |
| 設定だけ保存できてキーが失敗 | 「提供元の設定は保存しましたが、API キーを保存できませんでした。」に、キー保存が返した日本語の理由を続けます。例：「API キーの変更が拒否されました。登録状況を確認してください。」。設定欄を保存済みとして固定し、キーの空欄と「API キーを保存」、および「閉じる」を出します。再試行はキーだけです |
| 設定の保存中に、新しく付けた参照名のキーが別に登録された | 上と同じ部分成功の説明に、「設定を保存する間に、この参照名のキーが登録されました。上書きを避けるため、API キーを送信していません。この提供元は登録済みのキーを参照します。提供元の設定とキーを確認してください。」を続けます。キーは送りません。同じシートで再試行しても送りません。意図した共有なら、閉じて一覧の「API キー」か、開き直したフォームから登録できます。この画面には参照名を変える欄が無いため、意図しない共有の解消は、この画面の外（DSH の標準の設定など）で、どちらかの提供元の参照名を変えて行います |
| 保存後の一覧更新が失敗 | 「保存しましたが、一覧を更新できませんでした。再読み込みしてください。」。保存済みと失敗を区別し、追加を再送しません |

#### キャンセル・戻る・閉じる、スマートフォンでの配置

- **未保存変更の破棄確認は設けません。** キャンセル、見出しの閉じる、Escape、シートの終了操作、ブラウザーの戻る・画面移動は、すべて下書きを破棄します。通常時は「保存するまで変更は反映されません。閉じると入力中の内容は失われます」と補足します。共通オーバーレイは終了前の確認をすべての操作へ差し込む仕組みを持たないため、一部の操作だけに確認を置く案を採用しません。
- 送信開始後も閉じられますが、「保存を始めた変更は、閉じても取り消せません」と表示します。送信済み RPC の結果は一覧へ反映し、閉じたフォームを再表示しません。閉じる時点でまだ送っていないキーは破棄し、設定保存の成功を契機にあとからキーを送らないようにします。設定保存後の「閉じる」は保存済みの設定を戻しません。
- 連打・再オープンでも共通オーバーレイに閉じる処理を任せます。同じ対象で送信が残っている間は再編集を待ちます。終了アニメーションと背景の操作ロックが解放されたあと、元の入口へフォーカスを戻します。
- 幅 375〜390px では横並びの入力欄を作らず、長い名前と ID は折り返します。各操作のタッチ領域は 44px 以上。詳細の折りたたみとモデルの削除は明示した別ボタンです。
- 全画面シートは動的な画面高とセーフエリアに収め、本文を縦にスクロールします。末尾の操作列は画面全体への固定配置にせず、スクロールで必ず到達できる位置に置きます。キーボードが出ている間も入力欄・欄エラー・保存へ移動できることを確認します。初期表示で自動的にキーボードを出さず、フォーカスは見出しへ置きます。
- キーボードの実機確認は iOS Safari／PWA で行います。Playwright の狭い viewport の結果だけを、実際のソフトウェアキーボードの確認済みとは扱いません。

## そのほかの一覧と設定の画面

- **セッションの操作**：一覧の行を長押しすると開くシートです。「題名を変える」と「アーカイブ」を置きます。行を横にスワイプしてもアーカイブできます。
- **題名を変える**：会話の ⋮ や一覧の長押しから開くダイアログです（`ISession.rename`）。ワークスペースの名前の変更も同じ形にします。
- **セッションがないとき**：一覧の中央に「まだセッションがありません」と出し、＋ へ誘導します。
- **提供元と API キー**：提供元ごとに、キーが登録済みかどうかを出します。キーの入力はシートで、保存（`credentials.set`）と登録の削除（`credentials.unset`）ができます。入力した値は二度と表示しません。
- **外観**：「端末の設定に合わせる」「ライト」「ダーク」をシートで選びます。

## 画面遷移の決まり

- **下のタブ**（一覧・検索・対応待ち・設定）は、どこからでもほかのタブへ切り替わります。切り替えはフェードで、履歴を積みません。
- **奥の画面**（会話、設定の詳細、フォルダの選択、新しいセッション）は右から入ります。左上の ← と左端からのスワイプで、来た画面に戻ります。たとえば検索から開いた会話は、検索に戻ります。
- **シート**（＋、ツール承認、AI からの質問、記録の詳細）は下から出ます。返事をするか下に払うと閉じて、開く前の画面に戻ります。ただし、返事が必要なシートは払っても閉じません。
- **ドロワー**は左から出ます。ワークスペースを選ぶか外側をタップすると閉じます。
- 会話の「チャット / トレース」の切り替えは、同じ会話の中の表示の切り替えです。戻る操作の対象にはしません。
- 送信と停止は、同じ会話の状態（待機中と実行中）を切り替えるだけで、画面は移りません。

## 会話画面

- 上のバーは、戻るボタンとセッションの題名です。ナビゲーションバーは出しません。
- 上のバーの下に「チャット / トレース」のタブを置きます。
- 左端からのスワイプで、来た画面（一覧・検索・対応待ち）に戻ります。

### トレースタブ

- 出どころは今の画面の `dsh-client-ui-trajectory` と同じ記録です。対象は、ユーザー、アシスタント、ツール、サブツール、要約（compaction）です。
- ターンごとに見出しを付けます。見出しには、合計の所要時間とトークン数を添えます。
- 各行には、記録の種類（ツールは名前）、所要時間、トークン数を出します。失敗したツール（`isError`）は色で分かるようにします。
- 最新の記録から表示し、生成中は末尾を追いかけます。上にスクロールしたら追いかけるのをやめます。古い記録は「前の記録を読み込む」で読み込みます。
- 実行中の記録には開始の印だけを出し、経過時間を勝手に数えません。
- 行をタップすると、「記録の詳細」のボトムシートを開きます。中身は所要時間（最初の出力までの時間を含む）、トークン（入力・出力・キャッシュ）、入力、出力です。ツール呼び出しの引数は、トレースでは見られます。
- トレースを表示している間は、入力欄を隠します。送りたいときはチャットに戻ります。
- 入力欄の代わりに、下に検索バーを置きます（ユーザーが Canvas で追加）。トレースの記録を絞り込むものと解釈しています。
- トレースを表示中でも、ツール承認と AI からの質問のシートはその場で開きます。
- PC 版にある時間軸の図（ドラッグで範囲を選ぶもの）は、スマホでは出しません。

### 入力欄

- 角丸 28px の枠 1 つに、入力欄とボタンの行をまとめます。1 行のときの高さは約 110px です。
- 入力欄は最大 6 行まで伸び、それ以上はスクロールします。
- **Enter は改行です。送信はボタンだけです。**
- 下の行
  - 左：＋ ボタンです。ボトムシートを開き、画像添付、ファイル参照（`@`）、コマンド一覧、計画モードを操作し、モデルと考える深さをドロップダウンで選べます。
  - その隣：権限プリセットのチップです。常に表示します。
  - 右：送信ボタンです。
- **AI の実行中**
  - 停止ボタン（`ISession.cancel()`）を出します。
  - 送信ボタンはスプリットボタンにします。主ボタンは「順番待ち」で、▾ から「割り込み」を選べます（`prompt(content, mode)` の 2 つのモード）。
  - 順番待ちのメッセージは、入力欄の上に小さく出します。タップすると、編集、取り消し、割り込みへの変更ができます（`updateQueue`）。
- **候補リスト**：`/` でコマンドの候補（`CommandDescriptor`）、`@` でファイルの候補（`fileReferences.list`）を、入力欄の上に出します。
- **入力欄の外に出すもの**：統計とクォータは ⋮ から開きます。ツール承認と AI からの質問は、入力欄の上にボトムシートで重ね、返事が済むまで入力欄を隠します。
- **キーボード**：入力欄の位置は `visualViewport` に合わせます。画面全体の高さの計算には頼りません。iOS の Simulator でキーボードを出し入れしながら確かめます。

### チャットタブ

- 画面に出すのは `user/message`、`assistant/message`、`tool/result`、`system/message` の 4 種類です。知らない種類は読み飛ばします。
- 自分のメッセージは右寄せの吹き出しにします。添付した画像は小さく出し、タップで全画面に広げます。
- `user/message` でも、`source.kind` が `user` 以外のもの（指示ファイル、スキル、別の会話からの参照など、DSH が注入した文脈）は吹き出しにしません。「追加された文脈」の畳んだ行にして、出どころを添えます。`system/message`（システムプロンプト）も畳んだ行にします。
- 考えた内容（`reasoning`）は、ふだんは畳んでおき、タップで開きます。
- ツールの呼び出しは 1 行ずつ出します。ツール名に、引数の JSON から主な値を 1 つと、所要時間を添えます。JSON が壊れていたらツール名だけにします。失敗（`isError`）は色で分かるようにします。行をタップすると「ツール呼び出しの詳細」のシート（引数の整形、結果、所要時間）を開きます。
- コマンドの結果（`command/done`）は吹き出しにせず、小さな行で出します。
- メッセージを長押しすると「メッセージの操作」のシートを開きます。中身は「コピー」と「ここから分岐」（`sessions.fork` の `atSeq`）です。
- AI の処理が失敗したとき（`lastAgentError`）は、会話の最後にカードを出します。送信の失敗（`promptError`）は入力欄の上に小さく出して、もう一度送れるようにします。会話を開けなかったとき（`openState: error`）は、画面の中央に理由と「もう一度開く」を出します。

### 入力の補助

- `/` の候補と `@` の候補は、入力欄の上に出す浮いた一覧です。キーボードが出ている前提で、入力欄はキーボードのすぐ上に来ます。
- ＋ のシートの「画像を添付」は iOS の写真選択を開き、選んだ画像を入力欄の中に並べます。送る前なら × で外せます。
- ＋ のシートにモデルのドロップダウンを置きます。モデル一覧の取得中は読み込み中と示し、失敗時は理由と再試行を出します。考える深さは対応モデルを選んだときだけ表示します。
- 実行中の会話では、順番待ちのメッセージをタップすると「順番待ちの編集」のシートを開きます。中身は「編集」「今すぐ割り込ませる」「取り消す」です。

### 返事が必要なシートと選び直し

- **AI からの質問**：選択肢はラジオボタン（複数選択の問いはチェックボックス）で、下に自由入力の欄を置きます。1 回に複数の問いが来たら 1 問ずつ進みます。「あとで」はシートを畳むだけで、質問は対応待ちに残ります。
- **プランの確認**：全画面で開き、プランの本文（Markdown）をスクロールで読みます。ボタンは「直してほしい」（自由入力で修正を頼む）と、`intent.approve` の文字をそのまま使う承認ボタンです。
- **モデルの選択**：＋ のシート内のドロップダウンでモデルと考える深さ（`reasoningEffort`。対応するモデルだけ）を選び、その場で反映します。`/model` の送信では同じドロップダウンを持つシートを開きます。
- **権限の選び直し**：入力欄の権限のチップから開きます。説明文は `PresetOption.description` をそのまま出します。どのプリセットにも合わないときは「カスタム」と表示だけします。「フル アクセス」を選ぶときも確認は挟みません（2026-09-25 決定。実装後のフィードバックで見直す）。

### 会話の ⋮ メニュー

- 項目は「題名を変える」「統計」「ファイル」「ジョブ」「サブエージェント」「ゴール」「アーカイブ」です。
- **統計**：コンテキストの使用率、トークン、ターン数、モデルをシートで出します。値は projection から読みます。クォータは第 1 弾では出しません。
- **ファイル**：作業フォルダの中を読み取り専用でたどり、中身を表示します。テキストは 5,000 行ずつ読みます。
- **ジョブ**：動いているジョブと状態を並べ、実行中のものは止められます。止める API の形は未確認です。
- **サブエージェント**：子のエージェントを並べ、タップで子の会話を会話画面と同じ形で開きます。続けて頼めるものだけ入力欄を出します。
- **ゴール**：目標の文、状態、ラウンド数を出し、「一時停止」「完了にする」「ゴールを消す」を置きます。作成と編集は後回しです。

### ツール承認のシート

- 出せるのはツール名、理由、call id だけです。引数は届きません。
- ボタンは「許可（1 回）」と「拒否」だけです。「常に許可」はありません。

## Canvas のモックと実装の違い

Canvas は構造を確かめるためのもので、部品や動きに制約があります。実装するときは、次の点を Canvas の見た目ではなく、この仕様書に合わせてください。

- **ドロワー**：Canvas にスマートフォン用のドロワーの部品がないので、背景を暗くした画面に四角い枠を置いて描いています。実装では M3 のナビゲーションドロワー（モーダル）にします。
- **対応待ちから開いたシート**：Canvas では、承認のシートの背景が会話画面のままです。実装では、対応待ちの画面の上に出します。
- **戻る操作**：Canvas のスワイプは新しい画面を重ねる動きしかできないので、左端からのスワイプで戻る動きは描いていません。各画面のメモに書いてあります。
- **送信と停止**：Canvas では「待機中」と「実行中」の会話を別の画面として描いていますが、つないでいません。実装では同じ会話の状態の違いです。
- **一覧の行**：Canvas の 2 行目は「AI が実行中のセッション」の例として、実行中の会話につないであります。
- **接続が切れたとき**：状態を表す画面なので、ほかの画面からはつないでいません。
