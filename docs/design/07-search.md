# 07 検索タブ

## 目的

過去のセッションを、中身の言葉から探せるようにします。

## 担当する画面

| Canvas の画面 id | 名前 |
|---|---|
| `search` | 検索 |

仕様は `docs/ui-spec.md` の「検索タブ」の節です。

## 担当するファイル

- `web/src/features/search/` の全部（`routes.tsx` と `SearchScreen.tsx` は 00 の仮の部品を置き換える）
- `tests/07-*.test.ts`
- この設計書の「実装メモ」

## 入口

`routes`：`#/search`（下のタブ、`tab: 'search'`）。

## 画面の中身

- 上のバー「検索」の下に、検索バー「セッションを検索」を置きます。タブを開いたら検索バーに入力できる状態にしますが、キーボードを自動では出しません（iOS では画面が動くため）。
- **検索の呼び方**：入力が止まって 300ms 待ってから `sessions.search(query, signal)` を呼びます。新しい入力があったら、前の問い合わせを `AbortSignal` で中断します。空白だけの入力では検索しません。
- **結果の行**
  - 1 行目：セッションの題名。
  - 2 行目：一致した箇所の抜粋。一致した語を太字にします。抜粋が結果に入っていない場合は、「作業フォルダ名 ・ 最終更新日時」を出します（「未確認のこと」を見てください）。
  - 左のアイコンは、01 の一覧と同じモデルのアイコンです。01 の部品を読み込まず、`sessions.list` の `projectionValues` がなければ汎用のアイコンで構いません。
  - タップで `#/s/<id>` へ移ります。戻ると、検索の文字と結果、スクロール位置が残っています。
- 結果の上に「「<語>」の検索結果」と出します。
- `hasMore` が true のときだけ、最後に「さらに読み込む」を出します。押し方は「未確認のこと」を見てください。
- 検索中は検索バーの下に細い進捗バーを出します。
- 結果が 0 件なら「見つかりませんでした」。検索に失敗したら、理由と「もう一度検索」を出します。
- 何も入れていないときは、最近開いたセッション（`sessions.list` の `updatedAt` の新しい順に 5 件）を「最近のセッション」として出します。

## 使う DSH の窓口

- `sessions.search(query, signal)`：`RemoteResult<{ items: SessionSearchResultItem[]; hasMore: boolean }>`、上限は `sessions.searchResultLimit`
- `sessions.list`
- 00 の `navigate`

参考の実装：今の画面で検索を使っている部分（`dsh-client-ui-sidebar` など）。`SessionSearchResultItem` の中身はここで確かめてください。

## 偽データ（mock.ts）

- `kit.patch('sessions.search', …)` で偽の実装に差し替えます。セッションの題名と履歴の本文から語を探し、前後 20 文字を抜粋にして返します。応答を 400ms 遅らせ、中断を受けたら結果を返しません。
- 「承認」で 3 件、「zzz」で 0 件になるようにします。
- `?mock&scenario=search-error`：検索が失敗を返します。

## テスト

`tests/07-search.test.ts` で、次の純粋な処理を確かめます。

- 抜粋の中の一致した語の位置を探して、太字にする範囲を返す処理（大文字小文字、複数回の一致、一致なし）
- 検索するかの判定（空白だけ、前と同じ語）
- 「最近のセッション」の選び方

## 完了条件

- `?mock` で、入力に合わせた検索、中断、結果からの移動と戻り、0 件、失敗、最近のセッションが動きます。
- `pnpm typecheck`、`pnpm test`、`pnpm build` が通ります。

## 未確認のこと

- `SessionSearchResultItem` に抜粋（一致した箇所）が入っているか。入っていなければ、2 行目は作業フォルダ名と日時にします。
- 「さらに読み込む」の方法。`search` には続きを取る引数がありません。上限を上げて取り直すのか、続きは取れないのかを確かめ、取れなければ「さらに読み込む」の代わりに「さらに結果があります。語を増やして絞り込んでください」と出します。

## 実装メモ

### 2026-09-25 実装

- `SearchScreen()` と既存の `#/search` の入口を維持し、M3E の検索バー、検索結果の行、細い進捗表示、最近の 5 件、0 件、理由付きの失敗と再試行を実装した。入力に自動フォーカスはしない。
- 入力は前後の空白を除き、最後の変更から 300ms 後に検索する。空白だけ・正規化後に同じ語では再検索しない。日本語の変換中は問い合わせを保留し、確定後に待機を始める。
- 語が変わった時点でタイマーを解除し、直前の AbortController を中断する。中断を無視して届いた古い成功・失敗・例外も、signal と世代番号で無視する。画面を離れると通信を中断し、戻ったとき未完了の検索だけ再開する。
- 検索文字・結果・失敗状態・スクロール位置は、同じ `sessions` ごとの WeakMap に保持する。`navigate` で会話を開き、再表示時にスクロール領域へ位置を戻す。再読み込みをまたぐ永続化はしない。
- 抜粋は文字列のまま描画し、一致部分だけを `strong` にする。大文字小文字を区別せず、正規表現記号は文字として扱う。抜粋が空または未提供なら「作業フォルダ名 ・ 最終更新日時」を表示する。
- モデルは `projectionValues.modelSelection.lastUsed.model` を型ガードして読み、対応する SVG をこの機能に持たないため 01 と同じ頭文字の代替表示を使う。値がなければ Material Symbols の汎用アイコンにする。01 の部品には依存しない。

### 未確認事項を確認した結果

参照元の共通ディレクトリは `/Users/user/.npm-global/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/`。既存 UI と controller のコード・型を読むだけで確認し、DSH は起動・変更していない。

1. **抜粋はある。** `dsh-api-session-controller/lib/types/client/sessions/manager.d.ts:19-22` の `SessionSearchResultItem` は `{ sessionId: SessionId; snippet: string }`。題名等は含まれないため `sessions.list.byId` と結び付ける。ホストの抜粋上限は 240 Unicode code points（同 `lib/types/types.d.ts:156-163`、`lib/types/list.js:219-222`）。
2. **追加読み込みは公開されていない。** `searchResultLimit` は readonly の 20（同 `lib/types/client/sessions/service.d.ts:115-121`）、リクエストは query だけ（`lib/types/types.d.ts:244-251`）。ホストは固定上限を超える結果を `hasMore` にする（`lib/types/list.js:234-237`）。`dsh-client-ui-workspace/lib/types/client/contract/slots.d.ts:104-113` も hasMore は語を絞る必要がある状態と明記し、既存 UI は案内だけを出す（`lib/client.js:1963-1965,2658`）。上限を書き換えたり未公開の cursor を使ったりせず、設計指定の「さらに結果があります。語を増やして絞り込んでください」を採用した。
3. **中断はホストまで伝わる。** `dsh-api-session-controller/lib/types/client/contract/sessions.d.ts:74-83` と `lib/types/client/sessions/manager.js:440-441` で signal を渡し、`lib/types/list.js:152-153,165-166,184` で中断を判定する。既存 UI も timer と AbortController を解除して応答時の signal を確認する（`dsh-client-ui-workspace/lib/client.js:2092-2132`）。既存 UI の 250ms ではなく、この設計の 300ms に合わせた。
4. **モデル情報の形。** `dsh-api-session-controller/lib/types/types.d.ts:77-95` の `modelSelection.lastUsed` は `{ provider: string; model: string; reasoningEffort?: string } | null`。既存 UI の検索行はモデルロゴではなく状態マーク（`dsh-client-ui-workspace/lib/client.js:879-920`）。今回は 01 の頭文字・汎用アイコンの規則に合わせた。
5. 既存 UI は本文の検索結果に題名・ワークスペースのローカル一致を合流する（`dsh-client-ui-workspace/lib/client.js:489-552`）。実 API 単体が題名も全文検索するとは仮定していない。実画面は指定どおり `sessions.search` の結果を使い、偽データ側は設計指定に合わせて題名と履歴本文の両方を探す。

### 2026-09-25 レビュー指摘への修正

Codex と Claude のレビューで挙がった 6 件を、検索機能の担当範囲で修正した。

1. **変換中の表示と検索の保持。** 公開状態に `composing` と未確定入力の `phase: 'composing'` を加え、変換中は進捗と「検索しています…」を出さない。文字が変わらない変換開始では結果・スクロール位置・予約済み／実行中の検索を維持する。実際に語が変わると前の検索を中断し、確定後の 300ms 待機まで問い合わせを保留する。未確定入力のまま画面を出入りしても送信しない。
2. **削除した会話の除外。** 保存した応答自体は保持し、描画時に現在の `sessions.list.ids` と `byId` の両方で存在を確認する。削除後に戻ったときは、再検索しなくても結果から外れる。一覧の取得途中もメタデータのない行は表示を保留し、取得後に再評価する。取得途中の空表示を「見つかりませんでした」とは案内しない。
3. **表示対象の統一。** 既存 `dsh-client-ui-workspace/lib/client.js:338-340,502-533` に合わせ、最近の一覧と検索結果からサブエージェント・アーカイブ済み・一覧欠落を除外する。最近の一覧は選択中の空セッションだけを許可し、検索結果は選択中を含むすべての空セッションを除外する。最近の 5 件は除外後に選ぶ。`workspaces.list.archivedSessionIds` を購読するため、アーカイブの変更にも追従する。
4. **行高確定後のスクロール復元。** M3E 2.8.2 は内側ボタンの初回描画後に ResizeObserver を登録し、その通知から別の requestAnimationFrame で行数に応じた高さを更新する（`node_modules/@m3e/web/dist/list.js:136-138,174-189,817`）。外側・内側の `updateComplete` を待ち、この遅延処理を経た 3 フレーム目で位置を戻す。復元開始から次のフレームで保存を再開するまで、scroll イベントと cleanup による途中位置の保存を抑止する。語の変更、実際のスクロール操作、画面離脱、保存値の外部変更で古い復元を取り消す。一覧が取得途中なら復元自体を保留する。
5. **入力制限とエラー文言。** インストール済み `dsh-api-session-controller/lib/types/list.js:272-280` で、trim 後の上限が 500 UTF-16 code units、NUL が禁止と確認した。送信前に同じ判定を行い、上限超過・使用できない文字を日本語で案内する。絵文字等が 2 文字分になることも案内する。入力不正と `gateway/bad-request` には同じ語での再試行ボタンを出さず、語の修正を促す。`gateway/internal` は構成と動作状態の確認を促す文言に変更した。このコードは検索部品の欠落（同 `:149`）だけでなく検索処理の失敗（同 `:244`）にも使われるため、復旧後の再検索は可能にしている。
6. **テスト対象と実処理の一致。** `shouldSearch` を controller の変更判定、検索予約、再試行、復帰時の判定から呼ぶようにした。
