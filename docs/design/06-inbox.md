# 06 対応待ちタブ

## 目的

自分の操作が必要なものだけを 1 か所に集めます。複数のセッションを並行で動かしていても、どこで AI が止まっているかを一目で分かり、会話を開かずに返事を返せるようにします。

## 担当する画面

| Canvas の画面 id | 名前 |
|---|---|
| `inbox` | 対応待ち |

ナビゲーションバーの対応待ちの件数のバッジも担当します（描くのは 00、数を出すのはこの機能）。仕様は `docs/ui-spec.md` の「対応待ちタブ」の節です。

## 担当するファイル

- `web/src/features/inbox/` の全部（`routes.tsx`、`InboxScreen.tsx`、`count.ts` は 00 の仮の部品を置き換える）
- `tests/06-*.test.ts`
- この設計書の「実装メモ」

## 入口

- `routes`：`#/inbox`（下のタブ、`tab: 'inbox'`）
- `useInboxCount(): number`：00 のナビゲーションバーがバッジに使います。

## 画面の中身

- 上のバーは「対応待ち」だけです。
- 2 つの区分に分けて並べます。区分の中に何もなければ、その区分の見出しも出しません。
- **返事が必要**：00 の `usePendingInteractions()` の全部。届いた順（古いものが上）に並べます。
  - ツールの承認：アイコン `terminal`、1 行目はセッションの題名、2 行目は「ツールの承認：<ツール名> を実行しようとしています」。
  - AI からの質問：アイコン `help`、2 行目は「質問：<最初の問い>」。
  - プランの確認：アイコン `checklist`、2 行目は「プランの確認：承認するまで作業を始めません」。
  - タップで 05 の `presentInteraction(pending, { from: 'inbox' })` を呼びます。会話は開きません。返事を返すと、行が消えます。
  - 「あとで」の印（`defer`）が付いたものも、ここには出します。
- **終わったもの**：一覧のうち `completed` が true のセッション。新しい順に並べます。
  - アイコン `done_all`、2 行目は「完了 ・ <相対時刻>」（例：3 分前）。
  - タップで `#/s/<id>` へ移ります。開くと既読になり、この区分から消えます。
- 両方とも空なら、中央に「対応待ちはありません」と出します。
- 別のワークスペースのセッションも含めて、すべてを並べます。2 行目の先頭にワークスペース名を小さく添えます。

## 件数のバッジ

- `useInboxCount()` は「返事が必要」と「終わったもの」の件数の合計を返します。
- 0 件ならバッジを出しません（00 のナビゲーションバーが 0 を受けたら隠す）。
- バッジの付け方の注意：`@m3e/react` のバッジは React の `htmlFor` では `for` 属性が付かず、枠の外に出ます。ref で `setAttribute('for', アイコンの id)` とすると正しく付きます（`docs/handoff.md` の「部品集の実機比較」）。描くのは 00 ですが、件数を渡す形で困ったら 00 の実装メモを見てください。

#### 自分で決めたこと

- ワークスペース名は、土台が実物に合わせて公開する `useDsh().workspaces.list` を使う。設計本文の `ctx.remote.workspace.list` は使用しない。`sessionIds` の対応を優先し、未登録なら完全一致する `cwd` と `path` を補助にする。見つからなければ「ワークスペース未登録」、空の名前には日本語の代替表示を出す。選択中のワークスペースで絞り込まない。
- 返事待ちは共有 store が保持する到着順を維持し、`deferred` でも除外しない。複数の質問のどれかに `plan-review` があればプランとして扱う。未取得・削除済みセッションの要求も、共有 store に残る間は省略しない。
- 完了は一覧の `ids` にある `completed === true` だけを対象にする。同一時刻は一覧の順を維持し、欠損した行と重複 ID は件数に加えない。同じセッションに要求が複数あれば、それぞれを数える。
- 相対時刻は「たった今 / N 分前 / N 時間前 / N 日前」。完了行がある間だけ1分ごとに更新する。未来の時刻は「たった今」、不正な時刻は「時刻不明」にする。
- 長い題名・補足は行内で省略し、操作対象のアクセシビリティ名には全文を渡す。色・角丸・基本余白は共通テーマを使う。
- 偽データは `scenario=inbox` のときだけ5セッションと専用の2ワークスペースを追加し、他担当の通常シナリオを増やさない。承認・質問・プランは06からそれぞれ `kit.emit` する。`afterMs: 0` で次のイベントループに配信し、現在の土台でもハンドラ登録後に届くようにした。05 の偽データや秒単位の待ち時間に依存しない。
