# 11 画面の多言語化（日本語・英語・中国語）

## 目的

M3E の画面を、日本語に加えて英語と中国語（簡体字）でも使えるようにします（Issue #78）。言語は DSH の言語設定（`locale.preference`）に従い、未設定ならブラウザの言語に従います。

この設計書は、土台（`web/src/i18n/`）の決まりと、そのあとの機能ごとの移行・訳の追加の進め方をまとめます。最初の PR は土台だけで、画面の表示は変えません。

## 決まっていること（Issue #78、2026-10-12）

- 対象の言語は日本語（正本）、英語、中国語（簡体字）です。
- 未対応の言語は英語にします。
- 中国語は簡体字だけです。`zh`・`zh-CN`・`zh-Hans`・`zh-SG` は簡体字にします。繁体字（`zh-Hant`・`zh-TW`・`zh-HK`・`zh-MO`）は未対応として英語にします。
- 辞書は自前の型付き辞書にします。依存は足さず、`package.json` を変えません。
  - 機能ごとに `messages.ts` を置き、日本語を正本にします。英語と中国語は日本語と同じキーを持つ型にし、欠けや余りを型検査で落とします。
  - 数や値を差し込む文言は関数にします（例：`(count: number) => string`）。
  - 言語の決定、`lang` 属性、日付・数値・並べ替えの書式は `web/src/i18n/` にまとめます。
- DSH の `dsh-client-locale` の辞書には載せません。標準画面の用語集としてだけ参照します。
- 訳は AI が行います。用語は DSH 標準画面の英語・中国語の辞書に合わせます（例：会話、ツール、承認）。訳を足す PR には用語の対応表を置きます。
- 移し方は機能ごとに PR を分けます。

## 土台（`web/src/i18n/`）

| ファイル | 中身 |
|---|---|
| `locale.ts` | 言語の種類（`ja`・`en`・`zh`）、言語の決定（`requestedLocale`）、BCP 47 の言語タグの判定（`matchLocale`）、表示に使える言語（`DISPLAY_LOCALES`）、`lang` 属性の値（`documentLanguage`） |
| `format.ts` | 書式。`formatNumber`、`formatDateTime`、`compareText`（並べ替え）と、それぞれの `Intl` の部品（言語と指定ごとに使い回す） |
| `catalog.ts` | 辞書の型と `defineMessages`、言語ごとの取り出し（`messagesOf`）、実行時の検査（`catalogProblems`、`untranslatedLocales`） |
| `store.ts` | 言語の状態（DSH の設定とブラウザの言語から、求められた言語と表示する言語を出す） |
| `dsh.ts` | DSH の `locale.preference` の読み込みと、変更・再接続での読み直し |
| `current.ts` | 画面全体で 1 つの言語の状態（`localeStore`）と、React の外で使う `currentLocale`。DOM に依存しないので、`web/src/dsh/` の関数からも読める |
| `index.ts` | 画面全体で 1 つの状態、`startLocale`（`<html lang>` とブラウザの言語の追従）、`connectDshLocale`、React の `useLocale`・`useMessages`。`localeStore`・`currentLocale` は `current.ts` から再エクスポートする |

`main.tsx` は、起動の最初に `startLocale()` を呼び、DSH とつながったら `connectDshLocale(ctx)` を呼びます。

### 言語の決め方

1. DSH の `locale.preference` があれば、それを使います。対応しない言語なら英語です（ブラウザの言語には戻りません）。
2. なければ、ブラウザの言語（`navigator.languages`、`navigator.language` の順）を前から見て、最初に対応するものを使います。たとえば `['zh-TW', 'ja']` は日本語です。
3. どれも対応しなければ英語です。

- 判定は大文字・小文字を区別せず、`_` は `-` と同じに扱います。
- 中国語は、文字体系の指定（`Hans`・`Hant`）があればそれに従います（`zh-Hans-HK` は簡体字、`zh-Hant-CN` は英語）。指定がなければ、地域が台湾・香港・マカオのときだけ繁体字として英語にし、それ以外（`zh`、`zh-CN`、`zh-SG`、`zh-MY` など）は簡体字にします。
- DSH の設定値が DSH の形式（`^[A-Za-z]{2,8}(?:-[A-Za-z0-9]{1,8})*$`）に合わないときは、未設定と同じに扱います。

DSH の標準画面との違い：標準画面は、`zh-TW` のブラウザでも主言語の `zh` で中国語にし、設定値が未登録の言語ならブラウザの言語に戻ります（`dsh-client-locale/lib/client.js` の `detectBrowserLocale`・`resolveActive`）。M3E は上の決定に従い、どちらも英語にします。また、DSH が内蔵する言語は `zh` と `en` だけで、標準画面の言語の切り替えでは日本語を選べません。日本語の利用者が標準画面で English を選ぶと、M3E も英語になります（訳が入ったあと）。

### 表示に使える言語（訳がそろうまでの扱い）

- `DISPLAY_LOCALES`（`locale.ts`）に入っている言語だけを、画面の表示に使います。今は `['ja']` だけです。
- 英語・中国語を求められても、訳がそろうまでは、文言・`lang`・書式をすべて日本語のままにします。文言が日本語のまま `lang="en"` にすると、読み上げが英語の発音で日本語を読むなど、今より悪くなるためです。
- 求められた言語は `requested` に、実際の表示の言語は `active` に分けて持ちます。書式と `lang` は `active` に従います。
- 英語（または中国語）の訳をすべての辞書に入れた PR で、その言語を `DISPLAY_LOCALES` に足します。表示に使う言語に訳のない辞書が 1 つでもあると、単体試験（`tests/11-i18n.test.ts`）が失敗します。

### 辞書の書き方

```ts
// web/src/features/<機能>/messages.ts
import { defineMessages } from '../../i18n/catalog.ts'

export const inboxMessages = defineMessages({
  ja: {
    title: '対応待ち',
    count: (count: number) => `${count} 件`,
  },
  en: null, // 訳を足す PR まで null（日本語を表示）
  zh: null,
})
```

- 部品の中では `const text = useMessages(inboxMessages)` として `text.title`、`text.count(3)` のように使います。React の外では `messagesOf(catalog, currentLocale())` を使います。
- 訳は `defineMessages` の同じ呼び出しに書くか、別のファイルに分けるなら `satisfies Translation<typeof ja>` を付けます。どちらでも、キーの欠け・余り、文字列と関数の取り違え、関数の引数の型の違いが型検査で落ちます。
- `null` は「まだ訳がない」の印で、日本語を表示します。英語や中国語の文字列を仮に日本語で埋めることはしません。
- 1 つのファイルに複数の辞書を置いてかまいません。ファイル名は `messages.ts` にします（単体試験が `web/src/` の下の `messages.ts` をすべて読んで検査します）。
- 文の組み立てを言語ごとに変えられるよう、文の一部をつなぎ合わせず、差し込む値ごと 1 つの関数にします。単位（「件」「バイト」「秒」など）も文言に含めます。
- 値・ファイル名・モデル名・Host から届くデータは訳しません。

### 書式

- 日付・数値・並べ替えは `format.ts` の関数を使い、`'ja-JP'` や `'ja'` を直接書きません。言語ごとの `Intl` のロケールは、`ja-JP`・`en-US`・`zh-CN` です。
- 日本語の結果は、今の各機能の書き方と同じになることを単体試験で確かめています（`toLocaleString('ja-JP')`、一覧の `yyyy/mm/dd`・`HH:mm`、検索の日時、ファイル名の並べ替え）。
- 不正な日時は `formatDateTime` が `undefined` を返すので、呼び出し側で「日時不明」などの文言を出します。

### DSH の `locale.preference` を読む経路と根拠

DSH 0.2.0-rc.2 のパッケージ（`~/.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/`）を読んで確かめました。DSH は起動していません。

- `dsh-client-locale/lib/index.js:5,7`：設定の名前空間は `locale`、項目は `preference`。`:24` で Host 側のプラグインが `settings.configure({ auto: false })` を呼び、設定の一覧に `autoGenerate: false` の名前空間として登録します。
- `dsh-api-settings-controller/lib/index.js:392–397`：`ctx.remote.settings.describe()` は、登録済みのすべての名前空間を返します（`namespaceView` で `value`・`user`・`revision` などを付ける）。M3E の設定タブが使っているのと同じ窓口です。
- `dsh-settings/lib/index.js:435,461`：名前空間の文書が変わると、名前空間名と revision を付けて通知します。M3E の設定タブも `web/src/dsh/remote-events.ts` 経由で受けています。
- 標準画面の `dsh-client-locale/lib/client.js:1517` は `ctx.configForms.get('locale')` で同じ設定を読みます。M3E は `configForms` を読み込まないので、`settings.describe()` の `value.preference` を読みます。
- 偽データの設定一覧（`web/src/features/settings/mock-fixtures.ts`）は、実 DSH 0.2.0-rc.2 の `settings.describe()` を `e2e-dsh/rpc.spec.ts` で写したもので、`locale`（`autoGenerate: false`、`preference` は任意の文字列）を含みます。`e2e-dsh/rpc.spec.ts` は、偽データのすべての名前空間が実 DSH にあることを確かめる試験です。ただし、**この PR では実 DSH での確認をしていません**。

読み込みは、起動時に 1 回、`locale` の `settings/document-updated` を受けたとき、切断から接続に戻ったときに行います。読み込みは同時に 1 件で、その間の要求は 1 回の読み直しにまとめます。失敗したときは今の言語を保ち、画面には出しません（どちらの言語でも画面は使えるため）。`locale` 名前空間がない DSH では、ブラウザの言語に従います。

言語が変わると、`useLocale`・`useMessages` を使う部品が描き直されます。再読み込みは要りません（偽データと単体試験で確認。実 DSH は未確認）。

## 後続の PR の進め方

### 1. 機能ごとの文言の移行（日本語のまま、見た目を変えない）

- 1 つの機能を 1 つの PR にします。`features/<機能>/messages.ts` を作り、画面の日本語をそこへ移し、`en`・`zh` は `null` にします。
- 同じ PR で、その機能の書式（下の一覧）を `format.ts` の関数に置き換えます。
- 既存の e2e（`locale: 'ja-JP'`）と単体試験の日本語の期待値は変えずに通します。期待値を変える必要が出たら、表示が変わった理由を PR に書きます。
- 順番は、小さいもので型と書き方を確かめてから、大きいものへ進めます。
  1. 共通の部品（`web/src/app/`：ErrorBoundary、画面が見つからない、シート・スナックバーの共通文言、`remoteErrorMessage` など）
  2. 対応待ち（38）、検索（27）、会話（31）、質問・承認（32）
  3. ホーム（89）、チャット（86）
  4. 入力欄（142）、トレース（147）、セッションツール（149）
  5. 設定（297）
  - 数は Issue #78 の概算（文言の種類）です。
- 移行中の機能で文言を足すときは、辞書に足します。まだ移行していない機能は、その機能の移行 PR までこれまでの書き方のままでかまいません。

### 2. 英語・中国語の訳を足す

- 用語の対応表は `docs/i18n/glossary.md` に置きます（最初に訳を足す PR で作ります）。列は「日本語・英語・中国語・DSH 標準画面の辞書のキー（あれば）・メモ」です。DSH 標準画面の辞書（`dsh-client-locale` と各 `dsh-client-ui-*` の英語・中国語の辞書）の用語に合わせます。
- 訳は機能ごとの PR に分けてかまいません。すべての辞書に英語がそろった PR で `DISPLAY_LOCALES` に `en` を足し、中国語も同じようにします。
- 訳を足す PR では、`docs/i18n/glossary.md` に新しい用語を足します。

### 3. 言語の切り替えの e2e

- 表示に使える言語を足す PR で、e2e に言語の切り替え（DSH の設定・ブラウザの言語・未対応の言語・繁体字）の試験を足します。`e2e/i18n-foundation.spec.ts` の「訳が入るまでは日本語のまま」の試験は、そのとき期待値を改めます。
- 既存の e2e は `locale: 'ja-JP'` のまま通します。

### 移行のときに決めること

- 保存拒否の理由の表示（`web/src/features/settings/store.ts` の `displayableRejection`）は、日本語の文だけをそのまま表示する判定です。英語・中国語のときに Host の理由をどう扱うか（固定文言だけにするか、その言語の文字の判定を足すか）を、設定の移行 PR で決めます。
- Host から英語で届く文言（プランの確認のボタンの `Approve` など、05 の実装メモ）は、データとして訳さないか、既知の値だけ辞書で置き換えるかを、その機能の移行 PR で決めます。
- `web/public/manifest.webmanifest` の `lang` は `ja` のままです。マニフェストは静的なファイルで、言語ごとに分けられません。名前は「DSH」で言語によりません。`web/index.html` の `lang="ja"` も最初の値として残し、起動後に `startLocale` が言語に合わせます。
- 偽データ（`mock.ts` など）の日本語は、画面の文言ではないので訳しません。

## テスト

`tests/11-i18n.test.ts` で、次を確かめます。

- 言語の決定：設定値の優先、ブラウザの言語の順、未対応の言語、簡体字と繁体字、不正な設定値、表示に使える言語、`lang` の値
- DSH の設定の読み込み：`describe()` の形、偽データの DSH での変更の追従と解除、ほかの名前空間の通知、同時 1 件、失敗、再接続
- 書式：日本語の結果が今の書き方と同じこと、英語・中国語の結果、不正な日時
- 辞書：`web/src/` の全 `messages.ts` のキーのそろい、表示に使う言語の訳の有無、実行時の検査そのもの
- 型：`@ts-expect-error` で、キーの欠け・余り、関数と文字列の取り違え、引数の型の違いが型エラーになることを `pnpm typecheck` で確かめます（`tsconfig.host.json` が `tests/` を含む）。

e2e の `e2e/i18n-foundation.spec.ts` で、ブラウザの言語が `ja-JP`・`en-US`・`zh-CN`・`zh-TW` のどれでも、今は画面と `lang` が日本語のままであること、起動時と `locale` の変更の通知で DSH の設定を読むことを確かめます。

## 未確認のこと

- 実 DSH で、`settings.describe()` に `locale` 名前空間が出ること、標準画面の言語の切り替えで `settings/document-updated`（`locale`）が M3E に届くこと。根拠はパッケージのコードと、`e2e-dsh/rpc.spec.ts` で写した偽データです。統合時に実 DSH で確かめます。
- 言語を切り替えたとき、再読み込みなしで M3E のすべての画面に反映されること。仕組み（`useLocale` で描き直す）はありますが、移行した機能ごとに確かめます。
