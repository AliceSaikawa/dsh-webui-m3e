# 99 統合と実機での確認

段階 3 は、ユーザーが行います（2026-09-25 決定）。AI は、ユーザーに頼まれた確認や修正を手伝います。段階 2 の各ブランチが揃い、それぞれのレビュー（GPT-6-Astra、effort Max）が済んでから始めます。

## 目的

段階 2 の各機能を main にまとめ、偽データではなく実物の DSH と iPhone で動くことを確かめます。各機能の「未確認のこと」と「実装メモ」を読み、残った食い違いを直します。

## 担当するファイル

- すべてのファイル。ただし、機能の中身を大きく作り直すときは、その機能の設計書の実装メモに理由を書きます。
- `docs/handoff.md`、`docs/ui-spec.md`、`README.md` の更新

## 手順

### 1. マージ

- 段階 1 の main に、段階 2 のブランチを 1 本ずつマージします。順番は 01、02、03、04、05、06、07、08、09、10 です（会話まわりを先にそろえると、あとの確認が楽なため）。
- 設計書の決まりどおりなら、ファイルの衝突は起きません。衝突したら、どちらかの担当が範囲外のファイルを変えています。その変更の実装メモを読み、正しい担当の側に寄せます。
- 1 本マージするごとに `pnpm typecheck`、`pnpm test`、`pnpm build` を通します。

### 2. 偽データでの通しの確認

`?mock` で、次の流れを続けて操作します。

1. 一覧からワークスペースを切り替え、新しいワークスペースを追加する。
2. ＋ から新しいセッションを作り、最初のメッセージを送る。
3. 実行中に順番待ちと割り込みで送り、停止する。
4. 承認の要求（`scenario=approval`）に会話の中で答える。トレースを開いた状態でも答える。
5. 対応待ちから、質問とプランの確認に会話を開かずに答える。
6. 検索から会話を開き、← で検索に戻る。
7. ⋮ から統計、ファイル、ジョブ、サブエージェント、ゴールを開き、題名を変え、アーカイブする。
8. 設定で DSH の設定を 1 つ変え、外観を切り替え、今の画面に戻す確認のダイアログまで進む。

### 3. 実物の DSH での確認

`docs/handoff.md` の「検証用の DSH」の手順で、本番から切り離した DSH にプラグインを入れて確かめます。

- 段階 2 の各設計書の「未確認のこと」を 1 つずつ確かめ、結果を各設計書の実装メモに書きます。実装を直す必要があれば直します。
- 特に確かめること
  - 00：セッション 1 件の窓口の取り出し方、再接続したときに生成中の応答が途中から続くこと
  - 03：画像の送り方、モデルと権限の切り替え方
  - 05：承認と質問に答えたあと、AI の作業が続くこと
  - 06：会話を開いたときに「完了」が消えるか
  - 07：検索の結果に抜粋が入っているか
  - 08：スキーマの JSON の形と、設定の保存
  - 09：ジョブを止める窓口、ゴールの操作、ファイルのパスの形
- 本物の Mac の DSH と本番の Arch の DSH には入れません。トークンの扱いが必要な操作は、ユーザーに頼みます。

### 4. 本番の DSH の版

- ユーザーに `ssh archlinux 'dsh --version'` の実行を頼み、本番の版を確かめます（Claude Code の自動モードでは ssh が拒否されるため）。
- 同梱している `@deepseek-ai/cordis` と `@deepseek-ai/dsh-client-store` の版を、本番に合わせます。

### 5. iPhone での確認

iPhone 17 Pro Max（iOS 26.2）の Simulator の Safari と、ホーム画面に追加した Web アプリの両方で確かめます。

- キーボードの出し入れで、上のバーが画面の外に出ず、入力欄がキーボードのすぐ上に来ること
- シートを指で払って閉じられること、返事が必要なシートは払っても閉じないこと
- シートを開いている間、背景がスクロールしないこと
- ナビゲーションバー、シート、FAB が safe-area に隠れないこと
- 左端からのスワイプで戻れること
- ホーム画面に追加して開けること、Service Worker が `/m3e/` の下だけに効いていること、今の画面に戻せること

### 6. 仕上げ

- `docs/ui-spec.md` を、実装で決まったことに合わせて更新します。
- `docs/handoff.md` を、次のセッションが読んで分かる形に書き直します。
- ユーザーに、確かめた結果と、フィードバックをもらいたい画面を報告します。

## 完了条件

- main で `pnpm typecheck`、`pnpm test`、`pnpm build` が通ります。
- 上の 2 から 5 の確認が終わり、失敗したものは直したか、直せない理由と一緒に報告してあります。
