# 04 トレースタブ

## 目的

会話の記録を、ターンごと、処理ごとに並べて、どこで時間とトークンを使ったかを見られるようにします。今の PC 版の画面の「トレース」（`dsh-client-ui-trajectory`）をスマートフォン向けにしたものです。

## 担当する画面

| Canvas の画面 id | 名前 |
|---|---|
| `trace` | トレース |
| `record` | 記録の詳細 |

仕様は `docs/ui-spec.md` の「トレースタブ」の節です。

## 担当するファイル

- `web/src/features/trace/` の全部（`TraceView.tsx` は 00 の仮の部品を置き換える）
- `tests/04-*.test.ts`
- この設計書の「実装メモ」

## 入口

`TraceView({ sessionId })`。00 の会話画面がタブ「トレース」のときに描きます。このとき入力欄は出ません。

## 画面の中身

### 並べるもの

`useSession(sessionId)` の `records` と `stream` から、ターンごとの記録の列を作ります。

- **ターンの見出し**：`turn/start` から `turn/end` までを 1 つのターンとします。見出しは「ターン N ・ 合計 x 秒 ・ y トークン」。実行中のターンは「ターン N ・ 実行中」。
- **記録の行**：次の種類を 1 行ずつ出します。
  - ユーザー：`user/message`。2 行目に本文の先頭。
  - アシスタント：`assistant/message`。2 行目に所要時間と出力トークン。
  - ツール：`tool/call` と `tool/result` の組。1 行目は「ツール：<名前>」、2 行目に所要時間。失敗（`isError` か `error`）は色と「失敗」で示します。
  - サブツール：サブエージェントの中のツールなど、入れ子の記録。字下げして出します。
  - 要約（compaction）：会話を短くまとめた記録。
- 実行中の記録には開始の印だけを出し、経過時間を数えません。
- 画面に残らなかった試行（`assistant/attempt`）は、アシスタントの行に「再試行 n 回」と添えます。

### 時間とトークン

- 所要時間はイベントの `time` の差から出します。アシスタントは `step/start` から `assistant/message` まで、ツールは `tool/call` から `tool/result` までです。
- 最初の出力までの時間は、`assistant/message` の `stream` の最初の記録の時刻から出します。
- トークンは `assistant/message` の `usage`（入力、出力、キャッシュの読み書き）です。ターンの合計は、そのターンのアシスタントの `usage` を足したものです。

### スクロール

- 開いたときは最新の記録（一番下）から出します。生成中は、一番下にいる間だけ末尾を追いかけます。上にスクロールしたら追いかけるのをやめます。
- 一番上に「前の記録を読み込む」ボタンを置き、`hasMore` が true のときだけ出します。押すと `loadOlder()` を呼びます。

### 下の検索バー

- 入力欄の代わりに、画面の下に検索バーを置きます（ユーザーが Canvas で追加）。
- 入れた文字で記録の行を絞り込みます。対象は、記録の種類の名前、ツール名、本文です。絞り込み中も、ターンの見出しは残します。
- キーボードが出たら、検索バーはキーボードのすぐ上に来ます（00 の `viewport.ts`）。

### 記録の詳細

- 行をタップすると、下からシートを開きます。
- アシスタントの記録：所要時間（最初の出力までの時間を含む）、トークン（入力・出力・キャッシュ）、入力（送ったメッセージとツールの結果）、出力（思考・テキスト・ツール呼び出しの数）。入力と出力は、タップで中身を開きます。
- ツールの記録：引数（JSON を整形して等幅で。トレースでは引数を見られる）、結果、所要時間。
- ユーザーの記録：本文と添付。
- PC 版にある時間軸の図（ドラッグで範囲を選ぶもの）は作りません。

### 承認と質問

トレースを表示中でも、承認と質問のシートはその場で開きます。これは 00 の会話画面が扱うので、この機能では何もしません。

### 2026-09-25：トレースタブの実装

#### 実装したもの

- `TraceView({ sessionId })` の入口を保ち、ターン見出し、ユーザー・アシスタント・ツール・サブツール・要約の行、失敗の色と文言、実行中の開始印を実装した。
- 下の検索バーは種類名・ツール名・本文・引数を検索する。前後の空白、英字の大文字小文字、全角英数字を正規化する。絞り込みは読み込み済みの記録だけが対象で、全ターンの見出しと元の集計は残す。
- 初回の表示は末尾、末尾から48px以内にいる間だけ更新に追従する。上へ動かすと追従を止める。検索開始時は先頭に移り、検索中は追従しない。旧履歴の追加は表示中の行を基準に位置を復元する。非表示タブの高さが0の間は初期位置を決めず、表示されたときに処理する。
- 検索バーはトレース内部の固定フッターに置き、共通の会話フッターの余白と00のビューポート制御を使う。各部品はM3E、色は共通テーマの変数を使う。
- 詳細シートは開いた記録を更新し続ける。アシスタントの時間・トークン・入力と出力の展開、ツールの整形JSONと結果、ユーザーの本文・画像とファイルの情報を表示する。画像は押したときに `face.readAttachment()` で取得する。
- 偽データは専用ワークスペース「トレースの確認」・セッション「トレースの見本」（`trace-example`）。124件、18ステップの長いターン、未確定試行2件、2段のサブツール、要約、失敗、添付、実行中のターンを含む。既定100件から `loadOlder()` 1回で全件になる。共通の2セッションは変更していない。

#### 未確認だった事項を静的に確認した結果

参照元は、インストール済みDSHの `node_modules/@deepseek-ai/` 内の各パッケージ。読み取りだけで、本体の変更・起動・実接続は行っていない。

- **要約**：`dsh-client-ui-trajectory/lib/client.js:931–1016` で `compaction/start`・`compaction/summary`・`compaction/end` を `data.compactionId` で対応付けている。`summary` はContentBlock配列。`user/message` の `source.kind = plugin`、`plugin = compact` は入力履歴の置換で、通常ユーザー行として重複表示しない。
- **サブツール**：同ファイル `1536–1637`。`tool/ptc-dispatch-start` と `tool/ptc-dispatch` の `rootCallId`・`parentCallId`・`subCallId` で親子を解決する。終了側の本文は `data.content`、失敗は `data.isError`。通常ツールの結果は `message.source.callId` と `message.content` 内のtool-resultを使う。
- **所要時間**：同ファイル `7309–7362`。アシスタントはstep開始から確定メッセージ、ツールとサブツールは開始から結果、ターンと要約は開始から終了の時刻差。負の差は0にする。
- **最初の出力時刻は取得できる**：`dsh-llm/lib/types/assistant-stream.d.ts:16–40` と同 `assistant-stream.js:228–276`。通常記録は `time`、圧縮記録は `time0` と `dt` の累積。trajectory `client.js:591–599, 6380–6388` に合わせ、空でないテキスト・思考、引数の出力または名前付きツール差分を対象にする。block-start・usage・finishは対象外。開始から完了までの範囲にある出力だけを計測する。
- **トークン**：`dsh-llm/lib/types/types.d.ts:128–150` は入力を未キャッシュ分と定義している。trajectoryの各項目に合わせ、合計は入力＋キャッシュ読み込み＋キャッシュ書き込み＋出力。reasoningは出力の内数なので重ねて足さない。任意の `totalTokens` も加算しない。
- **再試行**：`dsh-session/lib/types/types.d.ts:319–327` の `assistant/attempt` は失敗・再試行・キャンセルなど、メッセージに確定しなかった試行全般。trajectory自体は `llm/retry` を扱う。今回の設計に従ってstepごとのattempt件数を「再試行 n 回」とし、詳細には「未確定の試行数」と補足する。両イベントを二重に数えず、未確定試行のusageもターン合計に足さない。

#### 自分で決めたことと制約

- ページ途中で開始記録が欠ける場合、直前の別イベントを開始時刻として代用せず「未計測」にする。途中のターンは開始前の記録が未読み込みと明示する。usageがなければ未記録とし、実行中の経過時間をタイマーで増やさない。
- `step/start` には送信内容そのものはない。詳細の入力は「読み込み済みの入力記録」と表示し、未読み込みの履歴や内部の指示を含む完全な送信内容とは扱わない。`dsh-session/lib/types/surface.js:257–273, 369–377` に従い、取得済みの `surfaceOp` の置換は末尾への追加ではなく元の位置への差し替えにする。
- user/messageがturn/startより前に来る場合も次のターンにまとめる。未知のイベント種類は行を作らず読み飛ばす。
- 画面のルートは00の会話ルートを使い、独自の重複ルートは登録しない。シートを入れ子にせず、詳細内で入力・出力を展開する。
- 既報の「タブを描いたまま隠す」土台修正は、オーケストレーターによる取り込み待ち。現在の土台はタブ切り替えでアンマウントするため、チャットの表示状態保持はこのブランチ単独では確認できない。共有ファイルは変更していない。
