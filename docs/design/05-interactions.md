# 05 承認・質問・プランの確認

## 目的

AI が人間の返事を待っているときのシートを作ります。返事がないと AI の作業が止まるので、どの画面にいても確実に気づけて、少ない操作で返せることを優先します。

## 担当する画面

| Canvas の画面 id | 名前 |
|---|---|
| `approval` | ツール承認 |
| `question` | AI からの質問 |
| `planReview` | プランの確認 |

仕様は `docs/ui-spec.md` の「ツール承認のシート」「返事が必要なシートと選び直し」のうち質問とプラン、「対応待ちタブ」の節です。

## 担当するファイル

- `web/src/features/interactions/` の全部（`InteractionSheet.tsx` は 00 の仮の部品を置き換える）
- `tests/05-*.test.ts`
- この設計書の「実装メモ」

## 入口

`presentInteraction(pending, { from })`。`pending` は 00 の `interactions.ts` が溜めた `PendingInteraction` です。

- `from: 'conversation'`：00 の会話画面が、そのセッションに返事待ちが来たときに呼びます。
- `from: 'inbox'`：06 の対応待ちタブが、行をタップしたときに呼びます。会話を開かず、対応待ちの画面の上にシートを出します。

同じ `pending` のシートがすでに開いていたら、2 つ目は開きません。返事をしたら、00 の `pending.answer(...)` を呼び、シートを閉じます。

## 画面の中身

### ツール承認

- シートの中身：見出し「ツールの承認」、「<ツール名> を実行しようとしています」、理由（`reason`。なければ出さない）。
- ボタン：「拒否」（`'rejected'`）と「許可（1 回）」（`'allowed-once'`）の 2 つだけです。「常に許可」はありません。
- **引数は届かないので、出せません**（API の調査メモ §9.1）。「何を実行するか」を詳しく見たいときのために、`callId` があれば「トレースで見る」の文字ボタンを置き、`#/s/<id>/trace` へ移ります。
- 下に払っても閉じません（`dismissible: false`）。会話画面から開いたときは、返事をするまで入力欄を隠します（00 の会話画面が、シートが開いている間は `Composer` を出さない）。
- DSH 側で取り消されたら（`signal` の中断）、シートを閉じ、スナックバーで「承認の要求は取り消されました」と出します。

### AI からの質問

- 1 回の要求に複数の問い（`items`）が入ることがあります。1 問ずつ出し、上に「質問 1 / 2」と出します。最後の問いのボタンは「回答する」、それ以外は「次へ」です。
- 各問いの中身：見出し（`header` があれば小さく）、問い（`question`）、補足（`detail`）、選択肢、自由入力の欄。
- 選択肢：単一選択ならラジオボタン、`multiSelect` ならチェックボックス。選択肢の説明（`description`）は 2 行目に小さく出します。
- 自由入力の欄「その他（自由に書く）」：単一選択では、書いた文が選択より優先されます（`custom`）。
- 選択肢がない問いは、自由入力だけにします。
- 「あとで」：00 の `defer(key)` で印を付けてシートを畳むだけで、答えは返しません。質問は対応待ちに残り、会話画面では入力欄の上に「返事待ちの質問があります」のチップを出して、タップで開き直せるようにします。このチップも、この機能のファイルに置き、00 の会話画面の仮の置き場に差し込みます（下の「会話画面への差し込み」）。
- 答えの形：`{ answers: [{ id, selected: string[], custom? }] }`（`AskUserQuestionAnswer`）。問いの一覧は pending の `items` ですが、答えのキーは `answers` です（段階 1 のレビューで、実物と土台に合わせて訂正）。

### プランの確認

- 問いの `intent.kind` が `'plan-review'` のとき、質問のシートの代わりに全画面のシート（`openFullSheet`）で開きます。
- 上のバー：× と「プランの確認」。× は「あとで」と同じ扱いです。
- 本文：`detail` の Markdown を 00 の `Markdown` 部品で描きます。長いのでスクロールします。
- ボタン：「直してほしい」と、承認のボタン。承認のボタンの文字は `intent.approve` をそのまま使います。
  - 承認：`selected: [intent.approve]` で答えます。
  - 「直してほしい」：複数行の入力欄を開き、書いた文を `custom` にして答えます。

### 会話画面への差し込み

00 の会話画面は、入力欄の上に「返事待ち」の表示を出す場所を用意し、`features/interactions/PendingChip.tsx` の `PendingChip({ sessionId })` を描きます。この部品もこの機能が作ります（00 は仮の部品として空のものを置きます）。

## 実装メモ

### 2026-09-25：段階 2 の実装

#### 実装したもの

- `InteractionSheet.tsx` の公開入口と戻り値を維持し、承認、質問、プラン確認を実装した。すべて `dismissible: false` とし、`interactionKey / sessionId` を 00 の overlay に渡す。会話の入力欄の表示制御は 00 の既存処理を使う。
- 承認はツール名、理由（ある場合）、`callId` がある場合の「トレースで見る」、拒否と 1 回の許可だけを表示する。引数と「常に許可」は表示せず、承認に「あとで」ボタンは設けない。
- 質問は 1 問ずつ進み、ラジオ、チェックボックス、選択肢の説明、自由入力を表示する。空の回答を送らず、最後に全問を `answers` へまとめる。前の質問にも戻れる。
- プランは全画面のシートで Markdown を読み、`intent.approve` の文字で承認する。「直してほしい」は複数行入力を開き、`custom` で修正を頼む。× は質問の「あとで」と同じく `defer(key)` のみで保留する。
- `PendingChip` は保留した質問とプランを開き直す。入力内容と質問の位置は要求のキーごとにメモリ内で保持し、回答・取消後に破棄する。ページ再読み込みをまたぐ保存はしない。
- 表示キューは同じキーを二重に開かず、先のシートを閉じてから次を開く。00 の到着順の待機一覧と組み合わせ、同一セッションの承認と質問を順に扱う。回答の多重送信を防ぎ、失敗時はシート内に日本語で再試行を案内する。
- 公開 pending に signal はないため、待機一覧からの削除を購読して取消を検出する。自分の回答による削除と区別し、承認の取消では「承認の要求は取り消されました」を表示して閉じる。質問の取消も閉じる。

#### 参考プラグインを読み取り専用で確かめたこと

参照元は、`npm root -g` で確認したインストール先の `@deepseek-ai/dsh/node_modules/@deepseek-ai/` 以下。DSH 本体の変更・起動はしていない。

- **承認の情報と返答**：`dsh-client-ui-approval/lib/types/client/contract/slots.d.ts:31–43` は `toolName / callId? / reason? / signal?` と、`allowed-once / rejected` だけを公開する。`lib/client.js:235–244` も同じ情報を取り出す。引数を出せない設計と一致する。
- **質問の回答**：`dsh-client-ui-user-questions/lib/client.js:537–549` は `{ answers: [{ id, selected, custom? }] }` を組み立てる。自由入力を trim し、単一選択では非空の自由入力が選択より優先され、複数選択では両方を返す。空の自由入力は省略する。今回も同じ回答の形にした。
- **プランの実装場所**：プラン確認は `dsh-client-ui-user-questions/lib/client.js:20–55,264–268` にあり、`dsh-client-ui-plan/lib/client.js:117–131` は計画モードのチップを担当する。
- **長く「あとで」にしたときの期限**：参照した 3 パッケージの `lib` では、クライアント独自の期限処理は見つからなかった。質問の `lib/client.js:840–859` は回答結果を待ち、同 `87–108` は signal の中断で `ASK_ABORTED` にする。同 `135–141` の `cancel()` は `ASK_CANCELLED` を返すため、保留には使えない。**ホスト側を含めた DSH の期限の有無は未確認**。段階 3 に残す。
- **同一セッションの承認と質問**：承認の `lib/client.js:235–246,271–283` と質問の `lib/client.js:840–845,873–881` は独立したイベントを受け取り、`scopeOf(owner)` でセッションに登録する。この範囲に両者の相互排他はないが、**実際に同時到着する実行条件は未確認**。既存 UI は種類の優先値を持つため、その表示順を到着順の根拠にはしていない。

#### 自分で決めたこと

- 到着順の扱いは本設計と 00 の待機一覧を正とし、表示要求は 1 枚ずつ処理する。取消済みの表示待ちは飛ばす。
- 参考 UI のプラン専用表示には「1 問だけ、本文あり、複数選択でない、選択肢 2 個以下、承認文字に一致する選択肢あり」という追加条件がある。今回は本設計と 00 の `isPlanReview` に合わせ、どれかの問いに `plan-review` があれば全画面にする。通常の問いが混ざっても順番に表示して全問を返し、プラン以外の問いを捨てない。承認文字は options がなくても intent から返す。
- 「トレースで見る」は回答せずに `defer(key)` で保留し、シートを閉じて対象のトレースへ移る。対応待ちからの移動では、会話への入場時に 00 が defer を解除しても、この移動についてだけ再保留し、すぐ承認が開き直すことを防ぐ。承認は対応待ちに残り、チャットへ戻ったときの承認チップからも再開できる。
- 回答がない状態では送信ボタンを無効にする。自由入力の前後の空白、重複した選択、届いていない選択肢を回答時に整理する。選択は勝手に初期確定しない。
- M3E のラジオとチェックボックスは本文スロットを持たないため、ネイティブ label 内に部品と説明文を並べた。ラジオグループの value は読み取り専用なので代入せず、各 radio の checked を制御する。依存や外部アセットは追加していない。
