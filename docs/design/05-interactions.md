# 05 承認・質問・プランの確認

## 目的

AI が人間の返事を待っているときのシートを作ります。返事がないと AI の作業が止まるので、どの画面にいても確実に気づけて、少ない操作で返せることを優先します。

## 担当する画面

| Canvas の画面 id | 名前 |
|---|---|
| `approval` | ツール承認 |
| `question` | AI からの質問 |
| `planReview` | プランの確認 |

仕様は `docs/ui-spec.md` の「ツール承認のシート」「返事が必要なシートと選び直し」のうち質問とプラン、「対応待ちタブ」の節です。

## 担当するファイル

- `web/src/features/interactions/` の全部（`InteractionSheet.tsx` は 00 の仮の部品を置き換える）
- `tests/05-*.test.ts`
- この設計書の「実装メモ」

## 入口

`presentInteraction(pending, { from })`。`pending` は 00 の `interactions.ts` が溜めた `PendingInteraction` です。

- `from: 'conversation'`：00 の会話画面が、そのセッションに返事待ちが来たときに呼びます。
- `from: 'inbox'`：06 の対応待ちタブが、行をタップしたときに呼びます。会話を開かず、対応待ちの画面の上にシートを出します。

同じ `pending` のシートがすでに開いていたら、2 つ目は開きません。返事をしたら、00 の `pending.answer(...)` を呼び、シートを閉じます。

## 画面の中身

### ツール承認

- シートの中身：見出し「ツールの承認」、「<ツール名> を実行しようとしています」、理由（`reason`。なければ出さない）。
- ボタン：「拒否」（`'rejected'`）と「許可（1 回）」（`'allowed-once'`）の 2 つだけです。「常に許可」はありません。
- **引数は届かないので、出せません**（API の調査メモ §9.1）。「何を実行するか」を詳しく見たいときのために、`callId` があれば「トレースで見る」の文字ボタンを置き、`#/s/<id>/trace` へ移ります。
- 下に払っても閉じません（`dismissible: false`）。会話画面から開いたときは、返事をするまで入力欄を隠します（00 の会話画面が、シートが開いている間は `Composer` を出さない）。
- DSH 側で取り消されたら（`signal` の中断）、シートを閉じ、スナックバーで「承認の要求は取り消されました」と出します。

### AI からの質問

- 1 回の要求に複数の問い（`items`）が入ることがあります。1 問ずつ出し、上に「質問 1 / 2」と出します。最後の問いのボタンは「回答する」、それ以外は「次へ」です。
- 各問いの中身：見出し（`header` があれば小さく）、問い（`question`）、補足（`detail`）、選択肢、自由入力の欄。
- 選択肢：単一選択ならラジオボタン、`multiSelect` ならチェックボックス。選択肢の説明（`description`）は 2 行目に小さく出します。
- 自由入力の欄「その他（自由に書く）」：単一選択では、書いた文が選択より優先されます（`custom`）。
- 選択肢がない問いは、自由入力だけにします。
- 「あとで」：00 の `defer(key)` で印を付けてシートを畳むだけで、答えは返しません。質問は対応待ちに残り、会話画面では入力欄の上に「返事待ちの質問があります」のチップを出して、タップで開き直せるようにします。このチップも、この機能のファイルに置き、00 の会話画面の仮の置き場に差し込みます（下の「会話画面への差し込み」）。
- 答えの形：`{ answers: [{ id, selected: string[], custom? }] }`（`AskUserQuestionAnswer`）。問いの一覧は pending の `items` ですが、答えのキーは `answers` です（段階 1 のレビューで、実物と土台に合わせて訂正）。

### プランの確認

- 問いの `intent.kind` が `'plan-review'` のとき、質問のシートの代わりに全画面のシート（`openFullSheet`）で開きます。
- 上のバー：× と「プランの確認」。× は「あとで」と同じ扱いです。
- 本文：`detail` の Markdown を 00 の `Markdown` 部品で描きます。長いのでスクロールします。
- ボタン：「直してほしい」と、承認のボタン。承認のボタンの文字は `intent.approve` をそのまま使います。
  - 承認：`selected: [intent.approve]` で答えます。
  - 「直してほしい」：複数行の入力欄を開き、書いた文を `custom` にして答えます。

### 会話画面への差し込み

00 の会話画面は、入力欄の上に「返事待ち」の表示を出す場所を用意し、`features/interactions/PendingChip.tsx` の `PendingChip({ sessionId })` を描きます。この部品もこの機能が作ります（00 は仮の部品として空のものを置きます）。

## 使う DSH の窓口

- 00 の `interactions.ts`：`PendingInteraction`、`answer()`、`usePendingInteractions()`
- 00 の `openSheet`、`openFullSheet`、`Markdown`、`showSnackbar`、`navigate`

参考の実装：今の画面の `dsh-client-ui-approval`、`dsh-client-ui-user-questions`、`dsh-client-ui-plan`。

## 偽データ（mock.ts）

- `kit.addSession` で「DB の選び直し」と「認証の作り直し」のセッションを足します（質問とプランの送り先）。
- `?mock&scenario=approval`：開いて 3 秒後に「承認シートの実装」へ `bash` の承認の要求を出します。
- `?mock&scenario=question`：「DB の選び直し」へ 2 問の質問（1 問目は単一選択と説明付き、2 問目は複数選択）。
- `?mock&scenario=plan`：「認証の作り直し」へプランの確認（Canvas の `planReview` の本文）。
- `?mock&scenario=approval-cancel`：承認の要求を出し、5 秒後に取り消します。

## テスト

`tests/05-interactions.test.ts` で、次の純粋な処理を確かめます。

- 質問の答えを組み立てる処理（単一選択、複数選択、自由入力が選択より優先される場合、選択肢のない問い）
- 問いの列から、プランの確認として扱うかの判定と、承認の答えの組み立て

## 完了条件

- `?mock` の 4 つの状態で、それぞれのシートが開き、返事を返すとシートが閉じ、偽の DSH が答えを受け取ったことがコンソールで分かります。
- 対応待ちから開いたとき（06 の仮の画面からでもよい）に、会話を開かずにシートが出ます。
- `pnpm typecheck`、`pnpm test`、`pnpm build` が通ります。

## 未確認のこと

- 質問を「あとで」にしたまま長く放置したとき、DSH 側で期限切れになるか。
- 1 つのセッションに承認と質問が同時に来ることがあるか。来たら、届いた順に 1 つずつ出します。
